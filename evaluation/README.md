# VISTAAR RAGAS Evaluation Framework

> Empirical Benchmark Suite for Retrieval-Augmented Generation Quality on the VISTAAR Platform.

---

## 1. Overview & Methodology

This evaluation module benchmarks the **VISTAAR** document question-answering architecture using the **RAGAS** (Retrieval Augmented Generation Assessment) framework across four core metrics:

1. **Faithfulness**: Measures factual consistency of the generated response against retrieved contexts (detecting hallucinations).
2. **Answer Relevancy**: Assesses how directly and completely the generated answer addresses the user query.
3. **Context Precision**: Evaluates the signal-to-noise ratio in retrieved context chunks, rewarding relevant chunks placed at higher ranks.
4. **Context Recall**: Measures the extent to which the retrieved context covers the ground-truth reference answer.

---

## 2. Architectural Analysis of VISTAAR Pipeline

Before evaluation, the VISTAAR pipeline components were analyzed as follows:

- **Document Ingestion (`ingestion.py`)**: Reads byte streams of PDF and plain-text files. Uses `PyPDF2.PdfReader` for page-by-page extraction, rejecting documents with $<50$ characters of text.
- **Semantic Partitioning (`chunking.py`)**: Slides a window of $L = 1000$ characters with $O = 200$ character overlap (stride $S = 800$), preserving cross-boundary semantic coherence.
- **Dense Vector Embedding (`embeddings.py`)**: Projects text chunks to a $d=384$-dimensional semantic space using `SentenceTransformer('all-MiniLM-L6-v2')`.
- **Vector Storage & Similarity Search (`vector_store.py`)**: Employs an exact in-memory `faiss.IndexFlatL2(384)` calculating Euclidean distance ($L_2$) to return top-$k=8$ chunks.
- **Strict Grounding & Answer Generation (`qa_service.py`)**: Formats retrieved chunks with separator tokens (`\n\n---\n\n`), passes them to Gemini with temperature $T=0.0$, and enforces negative refusal: *"I could not find this in the document."*

### Context Accessibility & The Smallest Isolated Solution
- **The Finding**: In the standard production server, `POST /ask` returns `{"answer": string}`, omitting raw context chunks from the response payload.
- **The Smallest Isolated Solution**: Rather than mutating production backend code or altering schemas, the evaluation collector imports `model` from `embeddings`, `search` from `vector_store`, and `ask_gemini` from `qa_service`. This executes the 100% identical pipeline while retaining direct access to `retrieved_contexts`.

## 3. Evaluation Dataset Structure

The benchmark includes **25 manually written test cases** structured into three distinct difficulty tiers:

| Category | Count | Description | Expected System Behavior |
|---|:---:|---|---|
| **Sufficient Evidence** | 12 | Direct questions answerable from corpus text | High Faithfulness, High Recall, detailed answer |
| **Partial Evidence** | 7 | Questions with partial information in corpus | Discloses available facts without speculating on unmentioned parts |
| **Insufficient Evidence** | 6 | Out-of-domain / unanswerable questions | Exact canonical refusal: *"I could not find this in the document."* |

Each record contains:
- `user_input`: The user question.
- `reference`: The ground-truth reference answer.
- `retrieved_contexts`: List of top-8 string chunks retrieved by FAISS.
- `response`: The actual answer generated by Gemini ($T=0.0$).

## 5. Interpreting Results for an IEEE Research Paper

When presenting these empirical results in an IEEE/ACM paper (typically in Section IV or V: *Experimental Evaluation & Results*), use the following analysis guidelines:

### 1. Faithfulness Score Analysis
- **Expected Range**: $0.95 - 1.00$.
- **Interpretation**: A high faithfulness score validates that the strict zero-temperature constraint ($T=0.0$) and system prompt effectively eliminate hallucinations. The model does not extrapolate beyond the retrieved 8 context chunks.
- **Refusal Behavior**: For insufficient-evidence queries (Q20–Q25), the model scores $1.00$ because it generates zero unsupported factual assertions, faithfully outputting the negative boundary token.

### 2. Answer Relevancy Score Analysis
- **Expected Range**: $0.85 - 0.95$.
- **Interpretation**: Evaluates whether the generated response directly answers the query without excessive verbosity or unrelated preamble. High cosine similarity between generated reverse questions and the original query indicates tight focus.

### 3. Context Precision Score Analysis
- **Expected Range**: $0.80 - 0.95$.
- **Interpretation**: Evaluates the ranking quality of `faiss.IndexFlatL2`. Top-ranked chunks contain the necessary evidence, verifying that the 384-dimensional `all-MiniLM-L6-v2` dense embeddings capture semantic intent over lexical overlap.

### 4. Context Recall Score Analysis
- **Expected Range**: $0.90 - 1.00$.
- **Interpretation**: Demonstrates that the chunking parameters ($L=1000, O=200$) and retrieval depth ($k=8$) successfully retrieve all key assertions needed to satisfy the reference answer.

## 6. Summary of Files in `evaluation/`

- `evaluate_ragas_standalone.py`: Standalone evaluator that computes the 4 RAGAS metrics with zero conflicting packages.
- `run_ragas_official.py`: Official RAGAS package runner for isolated virtual environments.
- `requirements.txt`: Evaluation-only package dependencies.
- `results/`: Directory storing all collected datasets and generated metric CSV files.
